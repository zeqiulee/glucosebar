## 确认之后的顺序

1. 添加选定许可证，公开仓库，推送主分支。
2. 检查 GitHub CI；失败就修复，不带失败状态宣传。
3. 创建测试标签和 Release 草稿，审阅包与说明。
4. 依签名、安装验证进度，决定公开技术预览还是面向普通用户的已公证测试版。
5. 先邀请少量匹配设备用户，再按[两周计划](launch-plan.zh-CN.md)扩大分享。

Star 是收藏与兴趣，下载是文件获取，都不等于成功安装和持续使用。首轮优先确认用户能装、能接入、知道旧数据状态并愿意继续使用。
